# Flows

## Conventions

Steps reference code as `` `function_name()` — src/kazbars/<module>.py `` — the backticked callable plus the file it lives in, **never** a line number. Line numbers rot on nearly every edit; function names survive refactors and are machine-checked: `tests/test_docs_in_sync.py` parses every step line, resolves each subject callable against the referenced file's AST, and fails CI on a rename or a reintroduced `:N` suffix.

When a flow crosses a dialog→app boundary (any modal `Toplevel` whose buttons or `WM_DELETE_WINDOW` callbacks invoke app methods), name the dialog-side dispatcher as an explicit step. Eliding it folds dialog-internal and app-internal responsibilities into one gloss and produces caller/callee confusion. Confirmed examples in this doc: Flow 4 step 3 (`AddGridWizard.on_create`), Flow 5 step 6 (`BuffSelectorDialog.on_ok`), Flow 13 step 5 (`start_empty`).

## 1. build and install SWF

Trigger: User clicks "Build & Install" button in the bottom bar or presses Ctrl+B

Steps:
1. `KazBarsApp._build()` — src/kazbars/app.py — one-line delegator to `build_action.build(self)`
2. `build_action.build()` — src/kazbars/build_action.py — checks `_building` re-entry guard; validates game folder, that there is anything to build (a grid or a shipping extra: cast timer, stopwatch, inspect panel, damage numbers, `console.ships()`, `onslaught.ships()`), and that no grid is over its own slot limit (`slot_count` vs `max_slots` — 64 on screen, 16 overhead; there is no total across grids); flags grids that would render empty (no whitelist or no static slot assignments); then `_declarations_gate()` blocks while any engine process is running via `get_running_engine_process()` — but only when `game_persistence.is_merged(app.game_path)` says the declarations aren't already spliced into the live game files: the client has to start with them in place for its archive to survive (THE STRIP RULE), and a patcher left open would strip the fresh archive on its own exit-save; once merged, `install_to_client` is an idempotent no-op and `/reloadui` handles the swap, so this fires on the first build ever and again on an upgrade whose client never got spliced
3. `get_profile_data()` — src/kazbars/grids_panel.py — calls `save_settings()` then returns `self.grids`
4. `save_settings()` — src/kazbars/grids_panel.py — iterates all `GridEditorPanel` instances, calling `save_to_config()` on each
5. `save_to_config()` — src/kazbars/grid_editor_panel.py — writes the card's one live control, the Enabled toggle, into the grid config dict (every other setting is written by Grid Settings' Apply, Flow 37)
6. `ProfileStore.flush()` — src/kazbars/profile_store.py — preceded by `app._on_grids_edited()` (src/kazbars/app.py), which mirrors the flushed grids into the store; then flushes the pending autosave before the build locks, so the built SWF always equals the saved profile and the `build_signature` snapshot hashes the synced document; the flushed profile's name feeds the summary's "Profile saved" line
7. `_build_worker()` — src/kazbars/build_action.py — build locks (`app._building = True`, build button disabled, Ctrl+B unbound), snapshots the Tk-thread inputs into a `ctx` dict — including `unresolved`, the count from `unresolved_refs()` (src/kazbars/grids_generator.py) of inert buff refs the generator will skip, for the summary's excluded-buffs line — and spawns this daemon worker so the compile + install run off the UI thread (mirrors `content_update`'s thread + `app.after(0, …)` marshalling — the loading animation never freezes). Steps 8–15 run on the worker; each phase label is posted back to the main loop and held at least `PHASE_MIN_MS` by `_hold_phase()` so it reads as a beat rather than a flash
8. `compile_to_staging()` — src/kazbars/build_executor.py — creates a `tempfile.mkdtemp` staging dir and calls `build_grids()`; returns `(staging_dir, (success, message))`. Forwards `cast_config` (read by `build_action` from the profile store's `cast_timer` section and validated up front via `cast_timer.validate_config`), `stopwatch_config`, `inspect_config`, `console_config` and `onslaught_config` (snapshot-copied by `build_action` off the store's sections so the worker thread never reads a live dict; validated downstream), `overlay` (the profile's `overlay` section: base size + font), `anchor` (this PC's `anchor_side`/`anchor_up` prefs, the overhead anchor) and `game_resolution` (extras positions are fractions like grid positions — projected to px at emit) to `build_grids`
9. `build_grids()` — src/kazbars/grids_generator.py — instantiates `CodeGenerator(..., cast_config=cast_config, console_config=console_config, onslaught_config=onslaught_config, overlay=overlay, anchor=anchor)`, writes every `(file name, source)` pair from `generate_files()` — `KazBars.as`, `KazBarsData.as`, `KazBarsData1..N.as` — to a second temp dir (the compiler binds file name == class name), writes the SWF to inject into with `font_base()` (src/kazbars/grids_generator.py: `base.swf` as shipped for Arial; for the game's Verdana `swf_font.import_game_font`; for a baked face `swf_font.splice` of `fonts/<slug>.bin` over the two embedded Arials; a failure returns "Couldn't set the overlay in {font}"), calls `compile_as2()` with all of them
10. `CodeGenerator.generate_files()` — src/kazbars/grids_generator.py — returns the `(file name, source)` pairs, main class first: `KazBars.as`, `KazBarsData.as` (`init()` builds `d`, emits the feature blocks below, then calls `KazBarsData<n>.fill(d)` once per chunk) and `KazBarsData1..N.as`. Only grids that ship are baked (`grid_ships()`: enabled, and a dynamic grid with a whitelist or a static one with a buff in a slot inside its shape; an empty grid is left out, never turned off), overhead bands last (`is_band`). `_data_units()` builds one source unit per grid — `_generate_grid_config()` emits its config (`iconSize`/`timerFont`/`stackFont` from `overlay_size.grid_metrics(base, scale)`, `timerStyle`, the overhead `plateOffset`/`maxDistance`/`maxSlots`/`showSelf`, `selfCastOnly`, `cls`) and its id set `d.WL[gid]` as `[id, fact code]` pairs (`_expand_primary_ids()` expands the refs, `_fact_codes()` / `fact_code()` pack each id's type, stack level and stacking family into one number) — then one per null-icon buff (`d.CUSTOMICON`); `_pack_units()` packs consecutive units under `DATA_CHUNK_BUDGET` (24K source chars) per `KazBarsData<n>` class because the compiler rejects any class over 32 KB of bytecode — a profile inside the per-grid slot limits referencing the whole catalog from every grid still compiles (`test_build_compile.py` pins the worst case and a no-chunking negative control). `generate()` is the joined-text wrapper (`main, data`) the unit tests read. The optional features gate their codegen here — `include_console` (via `console.ships`: enabled with at least one tab), `include_cast_timer` (via `cast_timer.is_enabled`), `include_stopwatch`, `include_inspect`, `include_onslaught` (via `onslaught.ships`: enabled with at least one display) and `include_overhead` (any baked overhead grid) toggle their `//#if CONSOLE|CAST|SW|INS|ONS|PLATE … //#end` gate blocks in `KazBars.as.template`, plus `CONBUFFS`/`CONCASTS`, one per console tab (each its own class) — the field, the construction, the registration into the core's `modules` array, that stub's `configure(…)` and its own feed calls, the lifecycle itself running off ungated loops over the array — kept or stripped by `_apply_feature_gates()` (src/kazbars/grids_generator.py, called from `_main_class()`), plus their `KazBarsData` block (`_cast_data_block`, `_stopwatch_data_block`, `_inspect_data_block` with `_inspect_rows_block` and `_pvp_view_block`, `_onslaught_data_block`, `_console_data_block`; each size is the module's `scale` applied to the overlay size by `panel_fs`/`cast_fs`), so a disabled feature leaves zero references and the compiler skips its stub class entirely (per-feature detail: architecture.md → Build pipeline). `_panel_font_data_block()` emits `d.PF = {fontSize, face, version, side, up}` **unconditionally** — the overlay base size itself (the preview control panel and the layout-preview labels draw at it), the face (`as2_face`: `_StandardFont` for Verdana, else Arial), the app version (`escape_as2_string(app_version)`, the control panel's footer credit) and the overhead anchor — because the preview control panel is never gated; the host's constructor always calls `ppanel.configure(d.PF)`
11. `compile_as2(classpaths, base_swf, sources)` — src/kazbars/build_utils.py — compiles in-process via `as2c.compile.compile_swf`, injecting the classes into `base_swf`; returns `(bool, message)` (mtasc-format error text on failure — `file:line: characters a-b : type error …`)
12. **(Damage Numbers — only when enabled)** `damageinfo_generator.build_damageinfo()` — src/kazbars/damageinfo_generator.py — `build_action` loads `damageinfo_settings` up front (validating the assets exist in the pre-build checks); if `enabled`, after the grids compile it bakes the offset settings into the lean AS2 tree and compiles a copy of the pristine `DamageInfo.swf` to `staging/DamageInfo.swf` (`loading.advance_step("Baking damage numbers...")`); a non-Hyborian `font` also rewrites the stock `DEFAULT_TEXT_SCALE` by `swf_font.dn_scale` and, after the compile, swaps the SWF's `_ConanFont` import for that face's embedded fonts via `swf_font.set_damage_font` (a failure there aborts like a compile failure). A bake/compile failure aborts before any install — both SWFs are staged before deploy, so nothing is partially installed. Disabled ⇒ `damageinfo_swf` stays `None`
13. `install_to_client(..., damageinfo_swf=..., damageinfo_pristine=...)` — src/kazbars/build_executor.py — `commit_damageinfo()` stages the one game-file change to a `.kaztmp` file (the slow copy), then the caller commits it with `os.replace` (the only lock-prone step) before copying `KazBars.swf` to `Data/Gui/Default/Flash/`, so a running-client file lock leaves the grids untouched. `_prepare_damageinfo()` stages the modded `DamageInfo.swf` install (capturing a one-time stock backup at `DamageInfo.swf.kazbars.bak` — seeded from the live file only when it is byte-identical to the bundled pristine stock, otherwise from the bundled pristine itself, so the backup can never capture a mod) or, when `damageinfo_swf` is `None`, a restore of stock from that backup. The build never touches the skin's `TextColors.xml` — per-source colors *and* directions are the Damage Number Colors panel's (Flow 21). Then declares the module permanently and drops the patcher-bypass flag (steps 14–15), and only once that succeeded clears the old load path (step 16). A `ValueError` from the splice (missing XML, damaged markers, non-UTF-8 text) is turned into a friendly failure naming the escape that always works — run the game patcher once, then Game ▸ Repair game install (Flow 29) — and leaves an upgrader's previous load path untouched, so a failed build never costs them a working overlay
14. `splice_declarations(game_path, discover_aoc_archive_declarations(game_path))` — src/kazbars/game_persistence.py — inserts a `<!-- KazBars begin/end -->` block before `</Root>` in `Data/Gui/Default/MainPrefs.xml` (the `KazBars` value + `KazBars settings` archive) and in `modules_target()` — `Data/Gui/Customized/Modules.xml` when that file exists, else `Data/Gui/Default/Modules.xml`. Idempotent: an existing block is refreshed in place, and a marked block stranded at the *other* Modules.xml location (a mod's Customized/Modules.xml appearing moves the target) is swept out along with its backup. Seeds a one-time `*.kazbars.bak` per XML before the first splice, and writes byte-faithfully (the XMLs are LF-only and the patcher hashes them)
15. `discover_aoc_archive_declarations()` + `ensure_flag()` — src/kazbars/game_persistence.py — other Aoc.exe mods' well-formed `<Value>`/`<Archive>` lines are adopted into *our* MainPrefs block (not their `<Module>` entries): a bare session that starts without their declarations would make the engine strip their saved archives. `ensure_flag()` then creates the empty `IgnorePatcher.enable` file in the game root, the engine-native flag that lets the client launch without respawning the patcher
16. `cleanup_legacy_files()` — src/kazbars/build_executor.py — runs **after** the splice and flag are in place, and clears every earlier way of loading KazBars: predecessor SWFs, all `Data/Gui/Aoc/` module folders in `LEGACY_AOC_DIRS` (**including our own `KazBars/`** — otherwise a still-active Aoc.exe would merge a second declaration on top of our permanent one), the `LEGACY_SCRIPTS` reload scripts, and via `clean_auto_login()` the `# KazBars auto-load` block
17. Success toast (one of two, success-styled, 8 s) — src/kazbars/build_action.py — `"/reloadui in-game"` when an AoC process is running, else `"launch the game"`. The success color and the build-loading screen carry the "it worked" signal; the toast is reduced to the next-action line
18. `notify_build_done()` — src/kazbars/grids_panel.py — marks step 4 of the in-panel tip guide complete, so the first-time user lands back on an all-green checklist once the summary screen is dismissed. A guide the user already dismissed is **not** re-shown. Step 4 un-ticks again the moment any subsequent edit fires `_mark_modified`, or a profile load calls `load_profile_data` (grids_panel.py). The guide itself is first-run only: `_update_tip` renders nothing once `self._onboarding` is false, latched at construction from `settings['has_built_before']` — which `_finish_success` flips (with one `save()`) just before calling this, alongside writing the `last_build` pref `{profile_id, profile_name, hash, target_resolution, anchor}` from the ctx snapshot (`build_signature` of the built document's BUILD-lane sections). `notify_build_done` then calls `refresh_build_status()` (grids_panel.py), so the status row under the extras cards flips to "In game: {profile}" the moment the summary shows; the completed checklist survives the session it was earned in and is gone from the next launch onward
19. `show_summary(..., game_running=…, flag_supported=…, unresolved=…)` — src/kazbars/build_loading.py — reload instructions are `/reloadui` when the game is running, else the two client exes to launch directly. `client_supports_flag()` (a chunked byte-scan of both exes for the flag string, run on the worker) gates an extra warning line for clients too old to skip the patcher; a patch-day line points at Game ▸ Repair game install either way. A non-zero `unresolved` adds a warning line — "N unresolved buffs excluded — a database update can bring them back" — the successor of the retired load-time missing-buff dialog
20. `_unlock()` — src/kazbars/build_action.py — runs on the main thread from `_finish_success` / `_finish_failure` / `_build_error`: cleans up the staging dir via `shutil.rmtree`, releases the `_building` flag, re-binds Ctrl+B, syncs build button state

End state: `KazBars.swf` installed under the game folder; the module is declared permanently in the game's own `MainPrefs.xml` + Modules target inside marker blocks, with a `.kazbars.bak` pair beside them and `IgnorePatcher.enable` in the game root — so positions saved to `Prefs_3.xml` survive a relog for every user, with no Aoc.exe and no reload scripts; every predecessor load path is gone; when Damage Numbers is enabled the modded `DamageInfo.swf` is installed (stock backed up to `DamageInfo.swf.kazbars.bak`), and when disabled any prior mod is reverted from that backup; the skin's `TextColors.xml` is left exactly as the color editor (Flow 21) wrote it — colors and directions both survive every build; build loading screen shows the result summary, and on the first successful build its dismissal chains into the desktop-shortcut offer (Flow 30)

## 2. open the profile at launch

Trigger: The app starts (and Backup & Restore's restore re-runs it, Flow 19). There is one profile, `userdata/profile.yml`; nothing switches it — File ▸ Import profile… and Reset profile to defaults… replace its document in place (Flow 24)

Steps:
1. `profile_io.startup_profile()` — src/kazbars/profile_io.py — called from `KazBarsApp.__init__` before `deiconify()`. Resolves the document down a ladder: (a) `profile.yml` exists → `read_profile_file()`; (b) it fails the gate → `_read_or_set_aside()` moves it to `profile.damaged.yml` (`profile.damaged-2.yml`… when one is already there) and the session snapshot `profile.yml.bak` is read instead (written back to `profile.yml`, toast "Your profile file was damaged — restored the copy from your last session"), or, when that fails too, (d) with "…no copy could be read — starting from the defaults"; (c) no `profile.yml` → `_adopt_library()`: every `userdata/profiles/*.json` of a 3.1 library through `read_profile_file()` (failures skipped), the one whose id the raw `prefs.json` still names as `active_profile` (or the caller's `active_hint`), else the newest by `file_mtime()` (0.0 for a file that vanished mid-scan) — written as `profile.yml`, `profiles/` never written, toast "Adopted “X” as your profile…"; (d) nothing → `_from_template()` instantiates the first template on `template_paths()` (OTA `content/Default.yml` while active, then stock) with a fresh id, `My Setup`, and the overlay size for the game resolution's height (`size_for_height`), else a blank `new_document()`; written as `profile.yml`. A failed write keeps the in-memory document (the store retries; the exit rescue dialog surfaces it). Then `make_store()` and `apply_document()`; toasts wait for the window (`app.after(0, …)`)
2. `profile_io.read_profile_file()` — src/kazbars/profile_io.py — `yaml_io.read_file()` — `.json` reads as JSON (a 3.1 document or `.kazbars.json` export), anything else as YAML shaped as JSON would be (keys always text); `profile_share.parse_profile_file` strips the `format` line (or unwraps the 3.1 envelope) and returns the embedded buffs; every read failure is the one `ValueError` "That file couldn't be read as a KazBars profile."
3. `validate_document()` — src/kazbars/profile_document.py — the single boundary: rejects non-documents, old-format profiles ("older KazBars"), and schema-above-current ("update the app"); strict coerce/clamp/drop inside registered sections, unknown sections preserved verbatim; older schemas climb the ladder first (the 2→3 rung `_overlay_scale` turns per-module px sizes into a percent `scale` of one `overlay.size`)
4. `profile_io.make_store()` — src/kazbars/profile_io.py — a `ProfileStore` whose writer is `write_profile()` (Flow 3) and whose session snapshot goes to `write_bak()`
5. `profile_io.apply_document()` — src/kazbars/profile_io.py — the dispatch step: grids into the panel, then `load_overlay()` (src/kazbars/grids_panel.py) shows the overlay size + font in the toolbar and redraws every card's Size hint, boss timer + Deeps (when alive), extras shortcut cards + in-game status row (`refresh_extras_shortcuts()`, which chains `refresh_build_status()` — the gates travel with the profile, and the row re-checks whether the installed SWF was built from the incoming document). The window title is just the app name (set once in `KazBarsApp.__init__`), never the profile's. At startup it must run before `deiconify()` so panels are populated before the window shows
6. `load_profile_data(grids)` — src/kazbars/grids_panel.py — iterates raw grid dicts; migrates, validates, rebuilds panel list; clears `_build_done` (what was built isn't what was just loaded); returns `{grid_name: [missing_refs]}` for buffs that couldn't be resolved
7. `_migrate_grid()` — src/kazbars/grids_panel.py — normalizes legacy `int` IDs and legacy name strings in `whitelist` and `slotAssignments` to current primary spell IDs via `database.by_id` and `database.get_entry_by_name`; unresolved refs are **preserved in place** (the profile autosaves — a load-time drop would destroy them within seconds) and reported for the warning
8. `validate_grid()` — src/kazbars/grid_model.py — fills missing keys from `create_default_grid()`; clamps every numeric field against `CLAMP_SPECS`; coerces enums in `ENUM_SPECS`; snaps a box's unfit fill to the order it draws in (`snap_fill`: a row `LR`, a column `TB`, else `TL-BR`); coerces booleans and lists/dicts; then `refresh_panels()` (src/kazbars/grids_panel.py) rebuilds the cards
9. Unresolved refs raise no dialog — `apply_document` logs them and moves on. They stay visible as greyed "unknown buff" rows in the buff selector (Flow 5, removable there on purpose), and the next Build & Install's summary reports the skipped count (Flow 1, step 19); a database update or import that supplies the buff revives them in place
10. If a Boss Timer panel is alive, `LiveTrackerPanel.load_profile_data()` — src/kazbars/live_tracker_panel.py — applies the section's `overlay` settings (`apply_settings` propagates opacity, font, lock, x/y through `set_*(..., notify=False)` calls, one `_notify_settings_changed()` at the end)
11. If a Deeps panel is alive, `DeepsPanel.load_profile_data()` — src/kazbars/deeps_panel.py — re-validates the `deeps` section, re-syncs the meter (`include_pet_damage`/`window_seconds`), pushes the whole config into the live overlay via `DeepsOverlay.apply_settings()` — src/kazbars/deeps_overlay.py — (layout, font, opacity, visible cells, lock, x/y — position/lock are quiet, no re-notify), then resyncs every panel widget via `_sync_widgets_from_settings()`

End state: panels show the profile; `profile.yml` holds it (a damaged file set aside as `profile.damaged.yml`, a 3.1 `profiles/` left as it was); positions are fractions (`fx`/`fy`) projected to px only at display and build time, so no resolution difference rewrites the document — `authored_at` is display-only provenance

## 3. profile autosave

Trigger: Any grid edit in the panel (add/delete/field change), an Overlay size/font change in the toolbar (Flow 32), a grid moved or copied to a class tab (Flow 33), a Boss Timer overlay change, an Extras dialog Apply or shortcut-card toggle (Flows 25–28), or Ctrl+S (manual flush)

Steps:
1. `GridsPanel._mark_modified()` — src/kazbars/grids_panel.py — panel-side dispatcher: un-ticks build step 4 of the tip guide and fires the app's `on_modified` callback. A card arms it via `GridEditorPanel._notify_edit()` (the card's `on_edit` callback — the Enabled toggle's `_on_enabled_toggled`, the Applied by me toggle's `_on_self_cast_toggled` (writes `selfCastOnly` only when on, pops it when off), and Grid Settings' `apply_settings`; a profile load builds fresh cards and never arms the autosaver); a card's whitelist/slot-assignment dialog commits via `GridsPanel._on_card_buffs_changed()` (refreshes the tip guide, then marks); structural add/delete/resize arrive on their own paths
2. `KazBarsApp._on_grids_edited()` — src/kazbars/app.py — deep-copies `get_profile_data()` (which flushes card widgets via `save_settings()` — src/kazbars/grids_panel.py) into the store's `grids` section, so later in-place panel edits can't bypass the store
3. `ProfileStore.set_section()` — src/kazbars/profile_store.py — updates the in-memory document and arms the debounced write (`DEBOUNCE_MS`, re-armed not stacked); the first mutation of the session first hands the pre-mutation document to `profile_io.write_bak()` (src/kazbars/profile_io.py), which writes `profile.yml.bak` — the snapshot behind File ▸ Revert to session start and the damaged-file fallback (Flow 2)
4. `ProfileStore.flush()` — src/kazbars/profile_store.py — the debounce firing (or Ctrl+S via `KazBarsApp._save_now()`, the pre-build flush in Flow 1, or app exit via `profile_io.release_store()` — Ctrl+S, the pre-build path and `release_store()` each call `_on_grids_edited()` first, so the store holds the cards' current state) cancels any pending timer and writes now
5. `profile_io.write_profile()` — src/kazbars/profile_io.py — the single writer: `validate_document()` → `profile_share.build_profile_file` (the `format: kazbars-profile` line first) → `yaml_io.dumps` → `safe_write_text()` (src/kazbars/settings_manager.py) atomic temp-rename to `userdata/profile.yml`; returns None on `OSError`
6. On write failure: `last_write_failed` is set, the store re-arms on the slower `RETRY_MS` cadence, and the exit path (`KazBarsApp._on_close()` — src/kazbars/app.py — via `profile_io.release_store()`) shows a rescue dialog instead of silently dropping edits

Boss Timer variant: `LiveTrackerPanel.save_settings()` — src/kazbars/live_tracker_panel.py — mirrors every overlay change into the document via the app's `on_boss_timer_profile_data()` hook (src/kazbars/app.py), so the `boss_timer` section stays current and survives the panel closing.

Extras variant: the five Extras dialogs (stopwatch, inspect, cast timer, console, onslaught) write their whole validated section via `ProfileStore.set_section()` on Apply, and the shortcut cards flip the gate flags via `ProfileStore.update_section()` — both land in step 3 like any grid edit.

End state: the document on disk equals the in-memory state within ~1s of the last edit (exactly, after any flush); no dirty flag, no Save prompt anywhere

## 4. add new grid via wizard

Trigger: User clicks "+ Add Grid" button on the grids panel toolbar (also reachable from the empty-state "Custom" preset card)

Steps:
1. `add_grid()` — src/kazbars/grids_panel.py — opens `AddGridWizard` dialog; no slot-budget check here — each grid has its own limit (there is no total across grids), enforced in the wizard
2. `AddGridWizard.__init__()` — src/kazbars/grid_dialogs.py — builds wizard UI: name, a kind picker (Floating: Player / Target, at a spot on screen; Overhead: Friendly / Hostile, over characters), mode, rows/columns and four preset shape buttons; `_on_type_changed()` swaps the presets (floating H-bar / V-bar / Grid / Single, overhead Row / Band / Grid / Single), the dynamic-mode blurb and the suggested name, and `_clamp_shape()` keeps the shape inside the kind's limit — 64 slots floating; overhead 16 slots, at most 4 rows × 8 columns; an overhead dynamic grid is a **band**, its columns the row cap (the spinbox steps 3, 5, 7; `snap_row_cap` reads the stored value as one of them) and its rows giving way to the 16 slots; calls `restore_window_position()`, then `fit_window_height()` — the dialog is fixed-size with no scroll, so it re-fits to the content height at the current Windows text scaling
3. `AddGridWizard.on_create()` — src/kazbars/grid_dialogs.py — validates name (non-empty, unique), enforces `max_slots` for the kind; calls `create_default_grid()`
4. `create_default_grid()` — src/kazbars/grid_model.py — returns a complete grid config dict populated with caller-specified `grid_type`, `rows`, `cols`, `mode`, `grid_id`; auto-coerces a floating `1×1` to static mode and picks a sensible `fillDirection`; an overhead grid also gets `plateOffset`/`maxDistance` (a friendly one `showSelf`), and an overhead dynamic grid its band keys (`rowCap`, `maxSlots`, centred fill `C`, shape derived by `band_shape`)
5. `_join_current_tab()` — src/kazbars/grids_panel.py — the new grid takes the class of the Grids tab it was made on (`_set_class`; the All tab leaves it classless), so it shows where the user is looking (Flow 33)
6. `refresh_panels()` — src/kazbars/grids_panel.py — destroys and recreates all `GridEditorPanel` cards; the cards are never expanded, so the new one simply appears in the list

End state: new grid config appended to `self.grids`; new `GridEditorPanel` card visible on the current tab; the edit is mirrored into the document and autosaved (Flow 3)

## 5. select tracked buffs for a dynamic grid

Trigger: User clicks the to-scale preview on a dynamic-mode `GridEditorPanel` (or Tabs to it and presses Enter/space); on a static grid the click lands on one cell and opens the same picker on that slot instead

Steps:

   - `meter.snapshot()` — read latest `MeterSnapshot` under the meter's lock
   - `_render_status(snapshot)` — colored line per status (idle/waiting/old/tailing)
   - `_update_alarm_state(snapshot)` — hysteresis: on at `dps >= alarm_threshold`, off at `dps < alarm_threshold * 0.9`

## 18. Deeps overlay auto-hide on AoC focus loss

Trigger: User alt-tabs away from AoC (to a browser, Discord, KazBars, anything else).

This is now a shared mechanism — the same `ForegroundWatcher` gates the Ethram-Fal overlay identically.

Steps:
1. **ForegroundWatcher tick** — src/kazbars/focus_watcher.py — the app-owned watcher ticks every ~250 ms on the Tk main loop, calling `foreground.app_or_game_foreground()` once. On focus change away from AoC + away from this process's own windows, the probe returns False.
2. The watcher calls `set_focus_suppressed(True)` on every registered overlay. `DeepsOverlay.set_focus_suppressed()` (src/kazbars/deeps_overlay.py) forwards to `HudOverlay`, which is state-guarded: it blanks the surface exactly once (one transparent `LayeredOverlay` blit), not every tick.
3. The Deeps meter keeps tailing; the 100 ms UI tick keeps calling `paint()`, which no-ops while suppressed (so no work + no re-blank spam).
4. User alt-tabs back to AoC → next watcher tick → `set_focus_suppressed(False)` → `HudOverlay` repaints if the overlay is wanted-visible → it reappears with the current numbers.

Subtle: clicking the overlay itself (to drag when unlocked) DOES count as "in focus" — `foreground.app_or_game_foreground()` checks `GetCurrentProcessId()` first, so any KazBars window keeps the gate open and drag-to-position never self-hides.

End state: overlay visibility tracks focus with ≤250 ms latency, for both overlays, from one probe. Lock state, position, and tracker data are preserved across hide/show — nothing is destroyed or reset.

## 22. OTA buff-database update on launch

Trigger: the one update check — `KazBarsApp.__init__` calls `update_orchestrator.check_on_launch(self)` after the layered DB load (returning user); on a fresh install `first_launch.on_dialog_closed` calls it once the welcome flow finishes (so an update never races the welcome popup). The orchestrator asks GitHub for a newer app release first (Flow 31) and reaches this flow only when there is nothing to install. Auto-runs only if the "Automatically update the buff database" toggle is on.

Steps:
1. `content_update.check_and_apply()` — src/kazbars/content_update.py — called from `_check_worker()` (src/kazbars/update_orchestrator.py) with the app's version and `prefs.content_version`; bails immediately if (auto and the toggle is off); otherwise spawns a daemon worker thread.
2. `_worker()` — fetches `ota/manifest.json` (raw URL on `main`); `parse_manifest` validates it. If `app_supports` is false (app older than `min_app_version`), schedules the once-per-session "New buffs are available — update KazBars" compat toast and stops. If not `is_newer(manifest, prefs.content_version)`, stops (manual run toasts "already up to date").
3. Downloads each SHA-pinned payload (`Database.json`, `Default.yml`); a `verify_sha256` mismatch aborts and swaps nothing. Then hops to the main thread via `app.after(0, _apply_on_main, …)`.
4. `_apply_on_main()` — **apply guard:** if `db_panel.modified` or `app._building`, defer (do nothing — retry next launch). Else `apply_content(content_dir(), …)`: snapshot the current `content/` into `.bak/prev/`, `os.replace` each verified payload into `content/`, then write `content/manifest.json` LAST as the commit marker (a crash between the replace and the marker re-applies next launch — never half-applied).
5. Persists `prefs.content_version = manifest.content_version`; `BuffDatabase.reload(content_update.active_content_db_path())` re-merges (stock←content←user) — the content layer is re-resolved at reload time and yields to stock when `content/` is below `CONTENT_BASELINE_VERSION`; `db_panel.refresh_from_database()`. A re-merge exception auto-rolls-back from `.bak/prev/` and toasts failure.
6. One `app_toast` — "Buff database updated — N added, M changed" (`summarize_changes`), click-through to a what-changed note + a Revert reminder. User deltas (`database_user.json`) are untouched throughout.

End state: `userdata/content/` holds the new stock `Database.json` + `Default.yml` + the `manifest.json` marker; `prefs.content_version` advanced; the live DB reflects the merge; `.bak/prev/` holds the prior content for Revert. Any failure or defer leaves everything on the shipped stock and changes nothing.

Checking the *current* target is what catches a UI mod that added a `Customized/Modules.xml` after us: our Default block is no longer the one the game loads, so this correctly reads as unhealthy
3. **Healthy** → `_refresh_repair_insurance()` — src/kazbars/game_folder.py — first `missing_archives()` (src/kazbars/game_persistence.py) asks whether the live `Prefs_3.xml` lacks anything the snapshot holds: a user who recovered by rebuilding rather than by Repair lands on this branch with the declarations back but the positions already stripped, so the re-injection has to live here too or it would never run. Anything missing is re-injected — unless an engine process is alive, in which case it warns and returns without snapshotting, since that process's exit-save would strip the re-injection right back out. Only then `snapshot_prefs3()` copies `%LOCALAPPDATA%\Funcom\Conan\Prefs\Prefs_3.xml` to `userdata/prefs3_snapshot.xml`, and only when that file still contains the `KazBars settings` archive, so an already-stripped prefs file can never overwrite a good snapshot. `ensure_flag()` re-creates `IgnorePatcher.enable` if something removed it. Every write on this path is best-effort (`OSError` logged, never raised): it runs during startup, so a read-only game folder must not stop the app from launching
4. **Unhealthy** → `app_toast(..., 'warning', 12, key='install_health', on_click=…)` — src/kazbars/ui_widgets.py — one coalescing toast whose click runs `repair_game_install(app)`; the menu item calls the same function
5. `KazBarsApp._repair_game_install()` — src/kazbars/app.py — one-line delegator to `game_folder.repair_game_install(self)`
6. `repair_game_install()` — src/kazbars/game_folder.py — guards on a configured, existing folder, then `_engine_blocks(app, "repair")` — src/kazbars/game_folder.py — which calls `get_running_engine_process()` (src/kazbars/build_executor.py, checks the two client exes **and** `ConanPatcher.exe`): the patcher saves `Prefs_3.xml` on exit too, so repairing under a live patcher run would have its shutdown strip the archives we just restored. A hit toasts "Close <process> first, then repair." and aborts
7. `discover_aoc_archive_declarations()` + `splice_declarations()` + `ensure_flag()` — src/kazbars/game_persistence.py — the same three calls the build makes (Flow 1, steps 14–15), so a patch-day repair restores exactly what a build would. A `ValueError` (damaged markers, non-UTF-8, or a file no longer XML-shaped) falls back to `strip_declarations()` — which restores each XML from its `.kazbars.bak` — and splices onto that known-good text; a second failure surfaces a Messagebox naming the escape that always works, run the game patcher once then Repair. `ensure_flag()` failing is not fatal on its own: it is logged and reported, and the repair continues
8. `cleanup_legacy_files()` — src/kazbars/build_executor.py — every pre-persistence upgrader reaches Repair through the step-4 toast (they have `has_built_before`, an old `KazBars.swf`, and no markers), so their `/loadclip` `auto_login` entry or `Data/Gui/Aoc/KazBars/` fragments are still live. Left in place the overlay would load twice, so the old load path is cleared once the new one is in place
9. `_restore_damageinfo()` — src/kazbars/game_folder.py — the same patch that restores the interface XMLs restores the stock `DamageInfo.swf`, so a Repair that skipped this would put the grids back and silently leave the numbers vanilla. When the mod's master enable is on, it rebakes from the saved settings via `damageinfo_generator.build_damageinfo()` into a `TemporaryDirectory` and commits through `build_executor.commit_damageinfo()` — the same stage-to-temp-then-single-`os.replace` path the build uses (Flow 1, step 13), so a running client's file lock is handled identically. Best-effort: a failed bake or a locked file is logged and reported, and the repair still counts as done — the declarations are what it exists for
10. `_reinject_managed_archives()` — src/kazbars/game_folder.py — named dispatcher: builds the managed set as `{'KazBars settings'} | archive_names_in(declarations)` — the adopted mods' archives are ours to protect too, since we are the reason a bare session preserves them — and calls `reinject_archives()` — src/kazbars/game_persistence.py — which copies whole `<Archive>` elements out of the snapshot **only** for names missing from the live `Prefs_3.xml`. A stale snapshot can therefore never overwrite a position the user has moved since
11. Result toast — src/kazbars/game_folder.py — success-styled, naming the restored archives when any were re-injected; warning-styled instead when the bypass flag couldn't be written, or when Damage Numbers is enabled but couldn't be restored ("run Build & Install to restore Damage Numbers")

End state: the marker blocks are back in `MainPrefs.xml` and the current Modules target, `IgnorePatcher.enable` exists, no predecessor load path remains to double-load the overlay, the Damage Numbers mod is reinstalled if it was enabled, and any archive the engine stripped is back in `Prefs_3.xml` — so the next launch loads KazBars once, with its saved positions. The snapshot is refreshed only while the install is healthy *and* complete, which is what makes it trustworthy insurance.

2. `_check_worker()` — src/kazbars/update_orchestrator.py — `update_check.fetch_release()` (src/kazbars/update_check.py): `'update'` (a newer tag) hops to `_offer_install` via `content_update._post`; `'error'` on a manual check toasts "Couldn't reach GitHub" and stops; anything else falls through to `content_update.check_and_apply(..., manual=manual)` — Flow 22 from its step 1.
3. `_offer_install()` — src/kazbars/update_orchestrator.py — main thread. One toast under the `app-update` key: "KazBars vX is available — click to install". A download already running is left alone; a tree already staged (`app._app_update_phase == 'ready'`) is re-offered through `_show_ready`.
4. `start_install()` — src/kazbars/update_orchestrator.py — **click 1** (also the About popup's entry): sets the phase to `'downloading'` and spawns `_install_worker`.
5. `_install_worker()` — src/kazbars/update_orchestrator.py — worker thread: `self_update.stage_release()` (src/kazbars/self_update.py) — `pick_assets` (the `KazBars.zip` + `.sha256` contract), free-space check, `stream_download` into `<install>/.update/KazBars.zip` (sha256 in the same pass; every whole percent hops to `_show_progress`, which re-emits the same toast as "Downloading … NN%" then "Unpacking …"), `parse_sha256_file` compare, `validate_zip` (zip-slip guard, single `KazBars/` root, exe present), `extract_staged` to `.update/KazBars/`, zip deleted, `pending.json` written (`state: staged`). Any failure removes `.update/` and raises `StageError` → `_show_failed` resets the phase and toasts "… — click to open the release page".
6. `_show_ready()` — src/kazbars/update_orchestrator.py — phase `'ready'`, staged exe remembered on `app._app_update_staged`; toast "KazBars vX downloaded — click to restart and install".
7. `restart_to_install()` — src/kazbars/update_orchestrator.py — **click 2**: `KazBarsApp._on_close()` (src/kazbars/app.py) runs the normal close path — the DB-editor unsaved guard and the profile flush-with-rescue may cancel, returning False, in which case nothing happens and the staged tree waits (the next check re-offers it). On True the window is gone; `self_update.spawn_apply()` launches the **staged** exe with `--apply-update --target <install> --wait-pid <pid>` (`spawn_detached`, `cwd` = install root, `CREATE_NO_WINDOW`) and this process exits.
8. `main()` — src/kazbars/__main__.py — in the staged exe: `self_update.parse_args()` sees the flag and calls `run_apply()` before any logging or Tk (`app_path()` would point at the staging dir).
9. `run_apply()` — src/kazbars/self_update.py — logs to `<install>/logs/update.log`; marks `pending.json` `applying` (attempts +1); `wait_for_pid()` (ctypes `OpenProcess`/`WaitForSingleObject`); `wait_until_writable()` on the install's exe — the real "nobody runs this install" signal (PID reuse, a second instance, AV still scanning); `plan_copy()` (skips `userdata/`, `logs/`, `.update/`; exe last); `apply_tree()` — phase A copies every file to a `.kbnew` sibling (a failure here unwinds to nothing), phase B is one `os.replace` burst; `prune_internal()` drops `_internal/` files the new build doesn't ship; marks `applied`; relaunches `<install>/KazBars.exe`. Any exception marks `failed` (error recorded), removes stray temps, and still relaunches the install's exe — the user is never left without an app.
10. `main()` — src/kazbars/__main__.py — the relaunched app: `startup_action()` (src/kazbars/self_update.py) classifies `.update/`; `'retry'` (an apply died under `MAX_APPLY_ATTEMPTS` with the staged exe intact) → `respawn_apply()` and return, before any window exists.
11. `finish_startup()` — src/kazbars/update_orchestrator.py — `KazBarsApp.__init__` schedules it 1.5 s after launch (the staged exe is still tearing down): `'updated'` (running version == `pending.version`) toasts "KazBars updated to vX — click for what's new"; `'failed'` toasts "The update couldn't be installed — click to download it manually"; then `discard_staging()` removes `.update/` (best-effort; leftovers go next launch).

End state: the install folder holds the new build with `userdata/` (profiles, prefs, user DB deltas, OTA content) and `logs/` byte-for-byte untouched, `.update/` gone, `logs/update.log` recording the apply. Files written by `urllib`/`zipfile` carry no Mark-of-the-Web, so the relaunch shows no SmartScreen prompt. A build older than the first self-updating release has no updater and is upgraded once by hand (extract the new zip over the existing folder).

5. `_buffs_changed()` — src/kazbars/grid_editor_panel.py — `_refresh_labels()` refreshes the summary and names line, then the card's `on_whitelist_changed` fires — `GridsPanel._on_card_buffs_changed()` — src/kazbars/grids_panel.py — which refreshes the step guide and calls `_mark_modified()` (the edit reaches the profile store and autosaves, Flow 3)
6. `GridPreview._clear()` — src/kazbars/grid_preview_canvas.py — right-click (`_on_right_click`) or Delete on a static cell that holds buffs calls the card's `on_clear(slot)`; an empty cell does nothing
7. `clear_slot()` — src/kazbars/grid_editor_panel.py — remembers the slot's refs in `_cleared` (entries older than 8 s are dropped), empties it with `_write_slot()`, runs `_buffs_changed()` (step 5), and raises an 8 s toast "Cleared slot N — click to undo" whose click runs `_undo_clear()`
8. `_undo_clear()` — src/kazbars/grid_editor_panel.py — refills every slot cleared while the toast showed that is still empty (a slot filled again meanwhile keeps what it holds now) with `_write_slot()`, then `_buffs_changed()`. It lands on the card `find_card` returns (`GridsPanel._card_for()`, src/kazbars/grids_panel.py — the card showing that grid now, so a rebuild within the toast's life does not strand the undo on a destroyed card); a grid gone from the list is left be, and a slot the grid shrank past stays cleared

End state: `grid_config['slotAssignments']` holds the slot's new refs, or no key for a cleared slot; the cell, summary and names line show it; the edit is marked modified and autosaved (Flow 3). Refs a slot picked from the dialog are written as stored (`entry['ids'][0]`; unresolved refs kept inert, as in Flow 5)

## 37. edit a grid's settings (the cog)

Trigger: On any `GridEditorPanel`, the user clicks the ⚙ cog beside the preview, at its top right (or Tabs to it — right after the preview — and presses Enter/space)

Steps:
1. `open_settings()` — src/kazbars/grid_editor_panel.py — the cog's command; delegates to `open_grid_settings(card)`
2. `open_grid_settings()` — src/kazbars/grid_settings_dialog.py — single-instance gate on `card.settings_dialog` (lift + focus if open); otherwise builds `GridSettingsDialog`
3. `GridSettingsDialog.__init__()` — src/kazbars/grid_settings_dialog.py — modal `Toplevel` (`transient` + `grab_set`) over the card's `grid_config`: cards Grid (Name; Rows × Cols, or a band's Row cap and Max slots; a screen grid's X / Y pixels, projected at `get_game_resolution_or_default()`), Icons (Size, Gap, Timers and Y offset, Flash and threshold), Overhead (overhead grids only: Height, Range, Over me) and Sorting (dynamic grids only: Fill, Sort, Order), each a label / field grid (`_field()` measures every label it makes; once the cards are built they share one label column, the widest label's width); `center_on_parent()` — src/kazbars/window_position.py — centres it on the app window, sized to its content. Applied by me is not here: it is the toggle on the card's title line, after the mode
4. `_changed()` — src/kazbars/grid_settings_dialog.py — every field edit rebuilds `draft()` (the settings the dialog owns; a box's shape and fill through `grid_model.settle_box`, the side typed into since the last settle (`_settled`, set at build and by `_on_shape`) giving way to the slot limit, a band's through `band_shape`; a moved X / Y rewrites its fraction through `unproject_px`) and hands it to `GridEditorPanel.preview_draft()` — src/kazbars/grid_editor_panel.py — which runs `_refresh_view()` on the config with the draft on top so the preview, summary and names line draw the draft live. Rows / Cols edits go through `_on_shape()` first (on an arrow, a focus-out or Enter — `labeled_spinbox` clamps on `<Return>`, its binding firing before the dialog's, so Enter applies the settled shape, and an emptied field gets its last committed value back; `grid_model.settle_box`: the edited one gives way to the slot limit and a dynamic 1×1 becomes 1×2, each with a toast; a dynamic grid's Fill choices follow via `_sync_fill_options()` and `grid_model.valid_fills`)
5. `GridSettingsDialog.apply()` — src/kazbars/grid_settings_dialog.py — dialog-side dispatcher (Apply, or Enter via `_on_return()`, which cancels instead when the Cancel button holds focus): takes `draft()`, asks `GridEditorPanel.name_problem()` — src/kazbars/grid_editor_panel.py — whether the name is empty or already another grid's (`name_in_use`); a problem shows under the Name field and the dialog stays open
6. `apply_settings()` — src/kazbars/grid_editor_panel.py — copies the draft onto `grid_config`; a box's shape goes through `settle_box()` again (src/kazbars/grid_model.py; the draft already settled it); a static grid's shrink runs `_trim_slot_assignments()` (stashing the dropped refs) and a regrow `_restore_orphaned_assignments()`; then `_refresh_view()`
7. `_notify_edit()` — src/kazbars/grid_editor_panel.py — `apply_settings()` always ends here, whatever moved; it fires the card's `on_edit` → `GridsPanel._mark_modified()`, and the edit reaches the profile store and autosaves (Flow 3)
8. `GridSettingsDialog.cancel()` — src/kazbars/grid_settings_dialog.py — Cancel, Esc or the window X; calls `GridEditorPanel.cancel_draft()` — src/kazbars/grid_editor_panel.py — which redraws from the stored config; nothing is written

Both `apply()` and `cancel()` go through `_close()` — src/kazbars/grid_settings_dialog.py — which destroys the dialog first (releasing its grab), then returns the card if it still exists, clearing `card.settings_dialog`, and the card call (`apply_settings` / `cancel_draft`) follows. Nothing rebuilds the card list under the dialog: `KazBarsApp._hotkey()` — src/kazbars/app.py — swallows shortcuts while this (or any) dialog holds the grab

End state: on Apply, `grid_config` holds the new settings and the card shows them; the profile is marked modified and autosaved (Flow 3). The dialog itself never writes the config; Cancel leaves it untouched

## 38. share grids (export a grid, import a grids file)

Trigger: A grid card's "Move…" ▸ Export grid…, or File ▸ Import grid…

Steps:
1. `GridEditorPanel._show_move_menu()` — src/kazbars/grid_editor_panel.py — after the Move to / Copy to cascades, a separator and "Export grid…", which calls the card's `on_export` callback (`GridsPanel.export_grid`)
2. `GridsPanel.export_grid()` — src/kazbars/grids_panel.py — `save_settings()` flushes the cards; `asksaveasfilename` with a suggested `<grid id>.kazbars-grids.yml` (through `profile_share.slugify`); `grid_templates.build()` (src/kazbars/grid_templates.py): `format: kazbars-grids`, `schema: 1`, the grid minus its `class`, and the user-provenance buffs it references (`profile_share.collect_for_refs` over the grids section's `harvest_refs`) — `yaml_io.dumps`, written atomically by `safe_write_text`; toast "Exported ‘<id>’ to “<file>”" plus "(+N custom buffs)"; a write failure (or a value YAML can't hold) is an error box
3. `KazBarsApp._import_grid()` — src/kazbars/app.py — File ▸ Import grid… (right under Import profile…): calls `profile_io.import_grids()` and, when it reports grids landed, `_switch_view('grids')` so they are seen; a cancel or a refused file switches nothing
4. `profile_io.import_grids()` — src/kazbars/profile_io.py — `askopenfilename` (KazBars grids `*.kazbars-grids.yml`, YAML, All files); `yaml_io.read_file()` (a read failure: "That file couldn't be read as a KazBars grids file."); `grid_templates.parse()` refuses a profile ("Use File ▸ Import profile… instead"), a newer schema or a file with no grids; the file's custom buffs merged first through `merge_embedded_buffs()` (skip on an id collision, rename on a name one) so the grids' refs resolve; then the panel; one toast: "Imported N grids into <tab name>" (`GridsPanel.tab_name()`), a "renamed ‘A’ to ‘A_2’ (name taken)" per rename, and the custom-buff phrases (`buff_merge_parts()`); returns True once grids landed
5. `GridsPanel.append_grids()` — src/kazbars/grids_panel.py — `save_settings()`, then `grid_templates.import_into()` (src/kazbars/grid_templates.py): each grid `validate_grid`'d, put on the current tab's class (`_tab_class()`; the All tab leaves it on every class), under `grids_generator.free_id()` (an id whose archive key is taken becomes `<id>_2`, the taken set growing across the batch); `_migrate_grid()` normalises the landed grids' refs as a load does (unresolved ones kept, greyed); the grids are appended, `_mark_modified()` autosaves them (Flow 3), `refresh_panels()` builds their cards; returns `(appended, renames)`

End state: a grids file holds the grids exactly as the profile does, without their class, plus the custom buffs they need; an import lands them on the tab it was made on, each under a name of its own, autosaved; nothing else in the profile changes
